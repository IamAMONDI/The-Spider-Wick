The Spider-Wick: Technical Codebase Guide

A concise cheat-sheet for the entire codebase so you can confidently answer any technical question.

1. Global Foundation (Used Everywhere)

The "Global CSS" approach: Instead of copy-pasting colors on every page, we use css/variable.css. It contains CSS Custom Properties (Variables) like --color-primary: #2D5A4A;. This file also holds the Global Navbar (.header, .link). If the navbar breaks or needs a color change, you only edit variable.css and it updates everywhere instantly.
Bootstrap 5: We use the Bootstrap framework for basic structure. Any time you see container-fluid, row, or col-md-6, that is Bootstrap automatically handling mobile-responsiveness for the basic text blocks.

2. Basic HTML Pages (Home, About, Mission, Contact)

These pages share a very similar, stable HTML structure built on standard best practices:

  • Semantic Tags: We use <nav> for the navigation bar and <footer> for the bottom section to improve Accessibility (Screen Readers) and SEO.
  • Hero Sections: Each of these pages features a "Hero" header (e.g. <div class="hero">). This uses CSS Flexbox (display: flex; flex-direction: column; justify-content: center;) to perfectly center the text vertically and horizontally, regardless of screen size.

3. Advanced Page: Gallery (gallery.html)

The Gallery uses an advanced "Masonry" layout so vertical and horizontal images fit together without gaps.

How it works (CSS Columns): Instead of a standard grid, we use column-count: 2; on the .bento-gallery wrapper. This acts exactly like newspaper text columns—images flow down the first column, then start at the top of the second. This prevents irregular gaps between photos of different heights.

4. Advanced Page: Impact (impact.html)

This is the most technically complex page, featuring modern layouts and scroll animations.

  • Bento Grid Layout: The statistics boxes use CSS Grid. The magic code is grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));. This tells the browser to automatically create as many columns as will fit, but never let them shrink below 300px. This makes it 100% responsive without writing a single @media query!
  • Grid Spanning: One stat box has the class .wide with grid-column: 1 / -1;. This forces that specific box to break the grid rules and stretch fully across the screen.
  • Scroll Animations (Vanilla JS): When you scroll down, the boxes slide up. This is powered by js/impact.js using the Intersection Observer API. It watches elements with the .fade-in class. When they enter the screen, it adds a .visible class, triggering a CSS transition (transform: translateY(0)). It's incredibly lightweight and doesn't require jQuery or heavy animation libraries.

5. Quick Q&A (For Random Technical Questions)

Q: What framework did you use to build this?
A: We built it entirely "Vanilla" (HTML, CSS, JS) using Bootstrap 5 just for the basic layout grid. This keeps the site extremely fast, lightweight, and easy to host statically on GitHub Pages without a build step.
Q: How do you handle Mobile Responsiveness?
A: A combination of three things: Bootstrap grid classes (like col-md-6), CSS Flexbox for components like the Navbar, and CSS Grid (auto-fit) for our advanced Bento grids which adapt to screen size automatically. For extreme cases, we use @media queries (e.g. dropping Gallery columns from 2 to 1 on mobile).
Q: Why did you use variables in CSS?
A: Maintainability. By storing our hex colors and fonts in :root variables, we guarantee visual consistency across all 6 pages. If we ever rebrand, we only have to change the color code in one single line of code instead of 50.
Q: How did you implement the scroll animations without hurting performance?
A: By using the native Intersection Observer API in JavaScript. Older sites use scroll-event listeners which fire hundreds of times a second and cause lag. Intersection Observer delegates the math to the browser's engine, making the slide-up animations silky smooth.
